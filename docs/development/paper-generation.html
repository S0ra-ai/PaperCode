Paper Generation

从输入到完整论文

本页说明 PaperRun 如何把主题、代码、数据和实验日志变成 Markdown/LaTeX/PDF/DOCX，并指出每一步对应的关键函数。

入口调用链

用户输入parsePaperWorkbenchPrompt 解析主题、材料路径和工作目录；submitPaperWorkbenchPrompt 调用 HTTP API 创建 PaperRun。
HTTP APIhandlers/paper.ts 的 create handler 调用 createPaperRun(normalizeCreatePayload(...))，并把错误包装成中文结构化诊断。
核心创建run.ts:createPaperRun 初始化 run 目录、事件、source/material index、stage graph、controller state 和 live snapshot。
研究执行orchestrator.ts:startPaperResearchRun 逐阶段运行 intake、planning、literature、code_analysis、data、experiment、claim、draft、review、export。
写作导出composeDraftPaper 生成论文式正文；exportPaperRun 根据 gate 写 final 或 blocked/forced draft bundle。

关键函数职责

函数位置输入输出/副作用修改建议

DraftPaper 章节策略

当前写作器不是把 ledger 原样贴进正文，而是把审计信息分层放置：主文使用论文术语，内部索引进入附录。

章节来源设计意图
摘要 / 引言 / 相关工作abstractSummary、introductionSummary、relatedWorkSummary、literatureEvidenceSummary、resultEvidenceText简述主题、证据链和终稿检查状态；相关工作读取 LiteratureMap.v1，只展示真实题名和可核验 locator；没有 result claim 时回退到 ResultReport 的主指标与基线证据。
参考文献referencesSummary、referenceEntry、referenceLocator只列入 verified source；未验证候选文献不得进入正式参考文献，只能显示需要 DOI、arXiv 元数据或人工审查验证。
研究问题researchQuestionsSummary围绕方法证据、实验有效性和复现一致性提出可检验问题。
主要贡献contributionsSummary把贡献写成研究对象和实验结论本身，并引用核心 method/result claim。
研究设计与证据流studyDesignSummary生成图 1 和阶段表，把材料、代码证据、协议、本机/容器执行和终稿检查串起来。
方法method claim、code analysis claim只描述已绑定 source range 的代码/方法，避免暴露内部实现词。
证据与可追踪性evidenceModelSummary用来源、断言、结构化记录解释正文可追踪性；内部索引细节放附录。
数据与代码可用性DataPlan、code sources说明数据、代码、许可和解释边界。
实验设置ExperimentPlan、ExperimentProtocol列出指标、基线、消融、预算和降级策略。
结果ResultReport、host/container runs用论文式实验比较描述本文方法与基线，不输出运行日志口吻的“复现实验记录/综合建议”。
可复现性reproducibilitySummary逐实验比较本机与容器指标，并列出实际运行摘要。
讨论discussionSummary约束结论范围，避免把持平或失败写成提升。
效度威胁threatsToValiditySummary明确构念、内部、外部、复现和自动化效度限制。
附录证据追踪、复现清单、断言证据表、证据记录索引、必要时的 starter pack保留审查细节；当 final claim 已放行时，不再携带过期修复清单。

写作器内部函数

函数职责常见修改点
scaffoldSections决定 DraftPaper 的章节顺序。新增/删除章节时先改这里，再补 authoring test。
render把 section array 转成 Markdown。只处理统一标题渲染，不应写业务逻辑。
markdownTable把结构化 rows 渲染为 Markdown 表格。表格字段新增时先在 summary 函数中准备 rows。
joinBlocks过滤空段落并用稳定空行连接。避免 TUI/Preview 中出现格式乱飘的多重空行。
normalizeCjkSpacing清理中文句号、问号、叹号后的英文式空格。claim 来自模型或脚本时可能混入 。 系统 这类格式，进入正文前统一规范。
paperProseText把底层证据文本转换成论文可读表述。将 source-range-grounded、source range、final gate、ClaimLedger 等实现词改成“基于源码范围的分析”“源码范围”“终稿检查”“证据台账”等正文表述。
displayMetricName / displayExperimentLabel把指标和实验 id 转成读者可理解的名称。typecheck_pass 显示为“类型检查通过状态”；container_reproduction_pass 显示为“容器复现通过状态”；baseline:baseline-toy 在正文中显示为 toy，避免把协议 id 当成论文文字。
displayExperimentRole / displayRunStatus把实验角色和运行状态转成正文表格语言。proposed 显示为“本文方法”，succeeded 显示为“通过”；Results 与 Reproducibility 表格不得回退成运行日志口吻。
resultEvidenceText为引言和相关工作提供结果证据。优先读取 result claim；没有 result claim 但有 ResultReport 时，用主指标、proposed 和最佳 baseline 构造可读结果句。
literatureEvidenceSummary把 LiteratureMap.v1 转成相关工作的文献表和边界说明。已验证来源显示为“相关工作”，并保留 DOI/arXiv/URL locator；英文摘要不直接塞进中文主文，而是显示“已核验英文摘要”和主题边界；只有未验证来源时显示为“候选文献”，明确不能作为领域共识或新颖性证明。
literatureDisplayTitle清理来源展示标题。只展示真实题名；外部检索尚未核验时只能形成缺口诊断，不能生成论文式候选题名。
referencesSummary生成正式参考文献章节。只输出 verified 文献的 title、DOI/arXiv/URL、published/retrieved 信息；未验证来源只写验证缺口，不列成正式引用。
citationText渲染正文中的引用标记。正文只显示 [来源 1] 这类可读标签，完整 source_id 只保留在附录、Preview annotation 和 manifest 中。
experimentRunSummary把 ExperimentRun.v1[] 转成实验运行表。新增 GPU、内存、数据集字段时从这里进入正文。
resultSummary把 ResultReport 写成主指标比较、复现结论和结果表。避免使用运行日志口吻；改 accept/revise/block 语义时同步 ResultReport 测试。

完整论文验收

当前 authoring test 要求当输入包含 ClaimLedger、DataPlan、ExperimentPlan、ExperimentProtocol、host/container ExperimentRun 和 ResultReport 时，composeDraftPaper 必须生成不少于 8500 字符的完整论文骨架，并包含研究问题、主要贡献、研究设计与证据流、证据与可追踪性、实验设置、可复现性、效度威胁、证据追踪附录、复现清单和登记命令。

主文在附录前不得暴露 ClaimLedger、artifact、final export、PaperRun、source-range-grounded、typecheck_pass、baseline:*、cite:*、material:code:* 等内部产品词、实现词、协议 id 或 source id；这些内容只能进入附录、manifest 或开发文档。

相关工作必须区分已验证来源与未核验候选。已验证来源可以作为相关工作进入正文并进入参考文献；未核验候选只能作为待查缺口，不能作为贡献、新颖性、实验结论或正式参考文献的论据。没有真实来源时，文献图保持为空并记录缺口。

这个测试的目的不是追求固定字数，而是防止回退到短报告、诊断日志或不可读占位稿。真实生成质量仍以 live benchmark 和人工阅读为准。

final 与 forced draft

final export 只能在 source、claim、citation、license、reproduction gate 全部通过时生成。缺 baseline、ablation、container 或 proposed 执行失败时，系统必须输出 blocked/forced draft，并把失败项写入 failed_checks。

final export 前会调用 refreshDraftPaperForFinalExport 重新读取最新 ClaimLedger.v1、ExperimentRun.v1[] 和 ResultReport.v1。如果用户修复实验后重跑，同一 experiment/environment 只取最新运行记录；旧失败 run 保留在 artifact 历史中，但不会进入终稿 Results、Reproducibility 或实验表格。

当最新 ResultReport.v1 的 final_claims_allowed 为 true，composeDraftPaper 不接收旧 ExperimentProtocolGuidance.v1 和 ExperimentProtocolStarterPack.v1。这条规则防止终稿一边显示复现通过，一边附带已经修复的缺口清单。

导出器不能把占位二进制伪装成成功文件。export-pipeline.ts 会校验 PDF 的 %PDF- 文件头和 DOCX 的 ZIP/OpenXML PK 文件头；无效或空输出会进入 tool_diagnostics，对应格式状态为 failed，不会写入最终文件列表。
