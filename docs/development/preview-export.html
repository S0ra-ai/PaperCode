Preview / Export

实时监控与导出链路

Preview 是 token-protected localhost 只读监控页。Export 负责 Markdown、LaTeX、PDF、DOCX 和 bundle manifest。

实时 Monitor

  • packages/preview/src/client.js 渲染 stage、draft、claim/source ledger、agent tree、cost、gate、export。
  • subscribePaperRunLiveMonitor 通过 SSE 接收 paper.run.snapshot。
  • Preview 只读；缺 token 或错误 token 必须拒绝访问。
  • 写作、引用、审稿、agent 调用、导出状态变化都应触发 snapshot 更新。
  • packages/preview/src/server.ts 的 SSE 服务设置 idleTimeout: 60，避免浏览器 smoke 中长连接被 Bun 默认超时提前关闭。

浏览器级验收

scripts/live-preview-browser-smoke.ps1 会启动真实 Preview server，并用本机 Chrome/Edge headless 通过 DevTools Protocol 打开监控页。它不是只测 HTTP JSON，而是覆盖 token 拒绝、只读写请求拒绝、SSE snapshot refresh、浏览器 shell 渲染、浏览器上下文读取 snapshot，以及客户端 bundle 中的实验运行摘要、终端 trace 摘要和机器环境字段。

浏览器 smoke 还要求 DOM 中直接出现 ExperimentTerminalTrace.v1 的 stdout 摘要。这样可以防止“JSON 有证据但页面看不见”的回退，也能暴露 client.js 模板语法错误导致的静态空壳页面。

报告写入 reports/live-preview-browser-smoke.md。当新增 Preview 字段时，应同步 smoke 中的测试 snapshot、浏览器断言和该报告说明。

机器与实验环境摘要

createPreviewMonitor 会把 PaperMachineProfile.v1 与 PaperExperimentEnvironmentStatus.v1 压缩成 monitor.machine_environment。该摘要包括工作区、默认 run root、OS/CPU/内存/磁盘、GPU 模式、runtime/compiler 列表、可选缺失数和阻断数。

Web 监控台只展示摘要，不展示完整 PATH 或环境变量。完整诊断仍保留在 PaperRun diagnostics，避免把本机细节过度暴露到只读 Preview 页面。

关键模块

模块职责
preview.ts把 draft、claim、citation、review、cost、agent 诊断转成 Preview snapshot。
export-pipeline.ts渲染 Markdown/LaTeX/PDF/DOCX，发现 Pandoc/LaTeX 工具。
research/export/recording.ts记录 export facts、manifest 和 export.bundle.completed 事件。
run.ts聚合 export_state，对格式、artifact_ids 和文件路径去重。

质量要求

  • final export 只能在 final gate passed 时生成。
  • final gate passed 但尚未重新导出时，export_state 必须保持 blocked，并报告 final_export_missing；旧 forced draft 不能冒充 final。
  • final export 前必须使用最新 ClaimLedger.v1、ExperimentRun.v1[] 和 ResultReport.v1 刷新 DraftPaper.v1；修复实验后不能把旧失败草稿导出为终稿。
  • final export 刷新只使用每个实验/环境的最新运行记录；旧失败记录可以留在 artifact 历史中，但不能污染 final 正文的 Results、Host/Container Consistency 或实验表格。
  • 当最新 ResultReport.v1 已允许 final claims，终稿不能继续附带旧 ExperimentProtocolGuidance.v1 或 starter pack 修复清单。
  • forced draft 可以生成，但必须保留 failed checks。
  • final 正文应体现复现实验指标，例如 proposed 与 baseline 的主指标。
  • 监控台展示的 artifact_ids 和 files 不能重复。
  • 当存在实验 starter pack，监控台必须显示 starter 文件、建议 scripts、apply endpoint 和推荐 payload；写入动作仍走受控 API，不在 Preview 直接执行写操作。
  • 当存在 ExperimentRun.v1[] artifact，监控台必须显示实验运行摘要，包括 host/container、命令、状态、退出码、耗时和指标。
  • 当实验协议由 PaperRun 受控重跑时，必须存在 ExperimentTerminalTrace.v1 artifact，并通过 experiment.command.started / experiment.command.completed 事件建立可审计执行边界。
  • Web 监控台必须默认展开终端 stdout/stderr 摘要；只显示字节数或 trace id 不足以支持用户判断实验失败原因。
  • 监控台必须展示 machine_environment 摘要，让用户知道当前实验是 GPU 还是 CPU-only、哪些 runtime/compiler 可用、哪些能力只是可选缺失。
  • 论文正文和 Preview 应使用同一份 ExperimentRun 来源；不能正文显示成功而 Preview 缺少运行摘要。
