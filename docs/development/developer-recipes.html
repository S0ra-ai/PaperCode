常见修改怎么做

这里按“我要改什么”给出文件清单、关键函数、测试和风险点。不要只改一个文件就结束。

新增 PaperRun Stage

  1. 在 stage id/type 定义里加入新 stage，并更新 stage graph 顺序。
  2. 在 orchestrator.ts:defaultHandlerFor 和 startPaperResearchRun 接入 handler。
  3. handler 输出必须写 artifact，metadata 带 artifact_schema。
  4. 在 run.ts snapshot 汇总新状态，必要时补 live event。
  5. 在 TUI dashboard 和 Preview 里显示 stage 状态。
  6. 测试：test/paper/paperrun-execution.test.ts 验证 stage 出现在 graph 且状态正确。

新增 Artifact Schema

packages/opencode/src/paper/research/**/schemas.ts
  1. 定义 schema version，例如 GpuEnvironmentReport.v1。
  2. 写入 artifact store 时填 metadata.artifact_schema、logical path、source_ids。
  3. snapshot 如果需要直接展示，增加 diagnostics/monitor 字段。
  4. Preview/TUI 只读展示，不直接读取任意文件路径。
  5. 测试 artifact 出现、schema 名正确、路径在 run_dir 内。

新增 TUI 页面

步骤文件说明
路由类型context/route.tsx新增 route data type。
入口命令app.tsx绑定 slash command 或快捷键，只暴露 PaperCode 语义。
页面组件routes/<page>.tsx组件负责布局和键盘交互，状态读取放到 util/workbench 层。

修改模型工作台

  1. 模型库存语义在 model-inventory.ts：candidate 只是发现，allowlist 才是可用。
  2. 新增 provider 注册字段时，同步 PaperModelInventory、normalize、load/save、HTTP handler。
  3. 路由决策必须走 routePaperModel，用户强制指定优先级最高，不可用时返回 blocked/pause。
  4. routes/paper-models.tsx 只展示用户已注册 provider 和可用模型，不能把未授权候选混入可用列表。
  5. 测试重启持久化、未配置空状态、allowlist 多选、主/备用决策模型和阶段策略。

修改论文正文

packages/opencode/src/paper/research/writing/draft.ts
  1. 正文结构在 scaffoldSections，新增章节要考虑 final 和 blocked 两种状态。
  2. 实验文案来自 experimentProtocolSummary、experimentSummary、experimentRunSummary、discussionSummary。
  3. 不要把长 artifact id、stdout/stderr、完整 claim ledger 放进正文；放附录或 artifact。
  4. 表格用 markdownTable，确保 Markdown、LaTeX、PDF、DOCX 都能稳定渲染。
  5. 测试 authoring/export，并实跑 scripts/live-paper-quality-benchmark.ts --scenario protocol 看真实输出。

让论文达到可读终稿

问题先改再验收
章节像报告而不是论文scaffoldSections、摘要/引言/相关工作/方法/实验/结论 summary 函数。生成 Markdown 后人工读主文，不只看测试通过。
格式乱、标题层级飘cjc-profile.ts、标题编号、表格渲染和导出 profile。Markdown、LaTeX、PDF、DOCX 都要检查；中国计算机学报 profile 是默认目标。
引用不可信LiteratureMap.v1、referencesSummary、checkReferences。只有 verified source 进入 References；没有真实来源时保持缺口诊断。
实验结果不能支撑结论ResultReport.v1、baseline/ablation/container 协议、terminal trace。缺实验时 final 阻断；有实验时正文要写本文方法、基线、消融和资源摘要。
正文暴露内部词paperProseText、displayMetricName、displayExperimentLabel。主文不出现 artifact、ClaimLedger、source id、baseline:*、typecheck_pass 这类实现词。

修改 Preview/实时监控

  1. 新增 monitor 字段时，先在 run.ts:createPaperRunLivePreviewSnapshot 生成。
  2. 同步 packages/preview/src/protocol.ts 类型和 src/client.js 渲染。
  3. TUI dashboard 使用 subscribePaperRunLiveMonitor 接收 SSE，不做独立事实计算。
  4. 只读约束必须保留：Preview 不允许写请求，不暴露 secret/path traversal。
  5. 跑 preview tests 和 browser smoke。

维护开发手册

  1. 新增模块或流程时，先在 module-map.html 标出目录边界。
  2. 新增关键函数时，同步 function-reference.html，写清输入、输出和不变量。
  3. 新增 HTTP API、event、artifact 或 snapshot 字段时，同步 api-contracts.html、paperrun-flow.html 或 preview-export.html。
  4. 新增用户可见工作流时，同步 usage-guide.html，但开发细节保留在开发页。
  5. 文档页面按“用途、参数、模式、输入/输出、调优、排障、下一步”组织，保持左侧导航和本页目录可用。

新增或重写开发文档页面

步骤文件验收点
定义页面职责目标 HTML 页面首屏说明该页解决哪个维护问题，不把使用教程和内部设计混在一起。
接入导航assets/manual.js 与所有页面侧栏左侧目录、搜索、上一页/下一页和“查看本页源码”都能工作。
写代码关联页面正文至少包含关键目录、关键函数、输入状态、输出 artifact/event/snapshot 和测试命令。
写修改路径developer-recipes.html说明开发者要改哪些文件、同步哪些契约、跑哪些检查。
写排障路径页面正文或 testing-maintenance.html常见错误要能映射到日志路径、诊断 code、测试文件和修复方向。
跑文档校验scripts/check-development-docs.ps1静态链接、页面清单、共享脚本、样式和可选浏览器渲染检查通过。

新增本机环境/GPU 页面

  1. 新增环境探测模块，使用 Node/Bun API 或受控命令采集 CPU、内存、GPU、CUDA、编译器、Python、Docker/Podman/Conda。
  2. 探测失败返回 not_configured 或 optional_missing，不要抛裸异常。
  3. TUI 侧边栏增加“机器/实验环境”页，显示可用、未配置、阻断缺失、建议操作。
  4. 将结果写入 PaperRun diagnostics，实验 runner 可以读取 GPU/容器能力决定是否暂停。
  5. 测试 Windows 中文路径、无 NVIDIA、无 Docker、Python 不存在、命令超时。
