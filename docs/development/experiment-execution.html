Experiment Runtime

代码实验、baseline、ablation 与复现

计算机类论文必须面对代码和实验。这里说明 Paper Fucker 如何发现脚本、执行命令、记录输出，并决定是否允许 final export。

执行模型

code_paths
  -> analyzeCodebaseForPaper
  -> ExperimentSurface / ReproductionPlan
  -> ExperimentProtocol discovery
  -> planExperiments
  -> runHostExploration
  -> runContainerReproduction
  -> analyzeExperimentResults
  -> ExperimentProtocolGuidance / StarterPack / final gate

关键文件

文件职责重点函数
orchestrator.ts把代码分析、协议发现、runner、ResultReport 串起来。defaultExperimentLoop、localCodeExperimentRunner、automaticCodeExperimentRunner、experimentProtocolGuidance
research/experiments/planning.ts根据 proposed、baseline、ablation 生成 ExperimentPlan。planExperiments、plannedExperimentSpecs
research/experiments/runner.ts执行 ExperimentSpec，生成 host/container ExperimentRun。runHostExploration、runContainerReproduction
research/experiments/analysis.ts分析指标、blocker、复现状态和最终结论权限。analyzeExperimentResults
run.ts把 starter pack 写入用户工作区，执行实验协议，记录终端 trace，并暴露 API。applyPaperRunExperimentStarterPack、runPaperRunExperimentProtocol、runExperimentShellCommand

协议发现规则

Paper Fucker 当前优先识别仓库 package.json 中的实验脚本。

脚本类型识别例子语义
proposedtypecheck、test、check、lint、bench被评估主方法。失败时不能进入 final。
baselinebaseline:bm25、baseline:toy对照组。缺失时生成 guidance，必要时阻断 final claim。
ablationablation:no-claim-ledger、ablation:toy消融组。缺失时贡献表述必须保守。
containerrepro:container、container:run隔离复现入口。失败时 final export 阻断。

真实性规则

automaticCodeExperimentRunner 只包装本地受控 runner，不把缺失的 baseline、ablation 或 container 脚本合成为成功结果。没有真实 runner 或显式 evidence manifest 时，final export 必须保持 blocked。

ExperimentRun 内容

字段来源用途
status命令退出码、超时、环境错误。进入 ResultReport blocker。
metricsrunner 解析结果或 pass/fail 转换。生成 Results 表和 best baseline。
stdout/stderr命令输出。正文只摘要；终端输出摘要和字节数由 ExperimentTerminalTrace.v1 保存。
resource_usage执行器采集。用于预算、GPU/CPU/内存展示。
reproduction.container_reproducedcontainer mode 成功。决定 reproduction gate 是否 passed。

Starter Pack

当仓库缺 baseline、ablation 或 container runner，系统生成 ExperimentProtocolStarterPack.v1，但它不是实验结果。applyPaperRunExperimentStarterPack 可以受控写入模板文件；传入 update_package_json=true 时，会把建议 scripts 合并进工作区 package.json，已有不同命令默认视为冲突，只有 overwrite=true 才覆盖。

Starter pack 的 package_json_scripts 只写入可落地的 starter 命令：baseline:starter、ablation:starter 和 repro:container:starter。Guidance 中的示例脚本只作为人类参考，不会默认写进用户仓库，避免用户点击“写入实验模板”后得到一组不存在的命令。

TUI 运行工作台会在 gate 区显示“写入实验模板”，点击后调用 /paper/runs/:runID/experiment-starter/apply，默认 payload 为 { dry_run:false, overwrite:false, update_package_json:true }。Preview 监控台的 monitor.experiment_starter_pack 同步暴露 apply_endpoint 和推荐 payload，便于前端把同一能力做成按钮。

  • experiments/starter/baseline-starter.ts：baseline 运行器骨架。
  • experiments/starter/ablation-starter.ts：消融运行器骨架。
  • experiments/starter/Dockerfile.repro：容器复现骨架。
  • experiments/starter/README.md：如何替换模板并重新运行。

受控重跑实验协议

runPaperRunExperimentProtocol 提供 PaperRun 级实验重跑入口。它读取当前 run artifacts 中最新的 ExperimentPlan.v1 与 ExperimentProtocol.v1，同时在执行前重新扫描当前 workspace 的 package.json。如果用户已经写入并补全 starter 脚本，重跑会生成一份 refreshed ExperimentProtocol.v1 artifact，并以新的 proposed、baseline、ablation、container 脚本重建本次执行计划。

HTTP 入口为 POST /paper/runs/:runID/experiments/run。默认可以 dry-run；TUI 工作台中的“运行实验协议”会发送 { dry_run:false, timeout_seconds:120 }，执行后写回新的 ExperimentRun.v1[]、ResultReport.v1 和 ExperimentTerminalTrace.v1 artifact，并发布 Preview snapshot。

输入字段作用
workspace_path指定执行工作区；缺省使用 PaperRun snapshot 的 workspace。
dry_run为 true 时只返回 planned commands，不执行命令。
timeout_seconds单条命令超时上限，当前限制在 1 到 900 秒。

终端 Trace

每条协议命令都会生成一条 ExperimentTerminalTrace.v1。它记录命令、cwd、环境、退出码、超时状态、耗时、stdout/stderr 字节数、输出截断标记和 64 KiB 以内的输出摘要。

事件流同时写入 experiment.command.started 与 experiment.command.completed。Preview 和 TUI 后续做实时终端视图时，应以这些事件作为状态边界，以 trace artifact 作为可审计证据。

当重跑后的 ResultReport.v1 允许 final claims，系统只会清除 reproduction_failure blocker；其他来源、引用或 claim blocker 会保留。此时如果还没有新的 final export，export_state 会报告 final_export_missing，用户需要再执行一次 final export；旧 forced draft 不会被当成终稿。

用户执行 final export 时，系统会基于最新实验 run 和 result report 刷新 DraftPaper.v1，再渲染 Markdown/LaTeX/PDF/DOCX。这样修复容器脚本后的终稿会显示“容器复现已通过”，不会继续携带旧草稿中的失败脚本或 reproduction_failure。

如果同一个 PaperRun 曾经有失败实验，终稿刷新只保留每个 experiment/environment 的最新 ExperimentRun。当最新 ResultReport.v1 的 final_claims_allowed 为 true 时，旧的 ExperimentProtocolGuidance.v1 与 ExperimentProtocolStarterPack.v1 不再进入终稿正文，避免论文一边通过 final gate、一边附带过期修复清单。

Preview 实验运行摘要

recordExperimentLoop 会写入 experiments/host-runs.json 与 experiments/container-runs.json，两者的 artifact schema 都是 ExperimentRun.v1[]。run.ts 读取这些 artifact 后放入 snapshot.diagnostics.experiment_runs，再由 createPreviewMonitor 压缩成 monitor.experiment_runs。

前端同时展示实验 run 摘要和终端 trace 摘要：环境、实验 id、角色、状态、命令、退出码、耗时、指标、stdout/stderr 字节数和截断标记。终端级输出以 ExperimentTerminalTrace.v1 artifact 为准，避免监控页承载过大的终端输出。

机器能力进入监控台

inspectPaperMachineProfile 在 PaperRun snapshot 中写入 machine_profile 与 experiment_environment。Preview 使用 monitor.machine_environment 展示 CPU/GPU 模式、runtime、compiler、虚拟化/容器工具和缺失能力统计。

这对代码论文很关键：当实验结果来自 CPU-only 环境、缺 Docker、缺 CUDA 或缺编译器时，用户能在监控台直接看到能力边界；论文正文也应保持对应限制，不能把未满足的环境写成已复现。

如何新增交互式终端执行器

  1. 定义执行接口：command、cwd、env allowlist、timeout、max output bytes、kill token。
  2. 在现有 ExperimentTerminalTrace.v1 基础上增加流式 chunk artifact，不破坏最终 trace 摘要。
  3. 把命令状态映射到 ExperimentRun.status：succeeded、failed、environment_failed、resource_exceeded。
  4. 把文件产物注册进 artifact store，避免只靠终端文本判断结果。
  5. TUI/Preview 订阅新增事件：command started、chunk、artifact written、command finished。
  6. 测试覆盖：成功、退出码失败、超时、中文路径、Windows shell、无权限、输出过长。
