测试、审计与维护

任何改动都应证明它让 Paper Fucker 更接近“可验证论文闭环”，而不是只让单个测试变绿。

常用验证

npx --yes bun@1.3.13 --cwd packages/opencode test test/paper/run-api.test.ts test/paper/model-discovery.test.ts
npx --yes bun@1.3.13 --cwd packages/opencode test test/paper/paperrun-execution.test.ts
npx --yes bun@1.3.13 run --cwd packages/opencode typecheck
npx --yes bun@1.3.13 --cwd packages/preview test
python -m unittest discover -s research-tools/tests
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-readme-version.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-changelog-format.ps1 -IncludeArchives

产品级验收

npx --yes bun@1.3.13 scripts/live-paper-quality-benchmark.ts --scenario code
npx --yes bun@1.3.13 scripts/live-paper-quality-benchmark.ts --scenario final
  • code 场景：无复现实验证据时 final export 应只因 reproduction gate 阻断；code claim 必须有 material:code:* source。
  • final 场景：带 SourceEvidenceManifest 和 ExperimentEvidenceManifest 时必须生成 final Markdown/LaTeX/PDF/DOCX。
  • 检查 summary 中 failed_checks=[]、preview=ready、artifact/file 去重。

维护清单

改动类型必须同步
新增 PaperRun artifactschema、recording、snapshot、Preview、测试。
新增模型/provider 行为model-inventory、TUI /models、API、secret scan、回归测试。
新增 TUI 页面命令白名单、终端尺寸、中文文案、错误页、截图或 smoke。
新增导出格式export schema、tool discovery、manifest、forced/final gate 测试。
新增能力包capability-pack、doctor、skill/MCP 安装检查、NOTICE。

TaskFlow 与版本

  • 新增工作要写入 TaskFlow confirmed task，执行后记录 step log。
  • 开发版本使用 -dev 后缀；进入 RC/release 流程时再切换版本语义。
  • CHANGELOG 使用 colon DSL，README 当前版本必须跟随根 CHANGELOG。
  • Git Flow 使用功能分支，合回 develop；除非明确确认，不操作 main、不打 tag。
