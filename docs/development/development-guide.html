Developer Guide

按产品链路修改 Paper Fucker

本页是开发主入口：先判断变更属于哪条链路，再定位模块、状态事实、UI 展示、测试和文档同步点。

页面写法按“参数、模式、输入、输出、调优、排障、下一步”组织，便于维护者像查 API 文档一样定位修改路径。

开发参数

参数含义落点
目标链路TUI、模型、PaperRun、实验、Preview、导出、文档或 release readiness。先在 docs/development/module-map.html 找模块边界。
状态事实用户可见状态必须来自 run、inventory、diagnostics、event 或 snapshot。避免只在 UI 中临时拼状态。
入口层TUI 命令、HTTP API、CLI 自动化、Preview 或 research-tools。入口只做编排，领域规则下沉到 Paper Core。
验证层单测、typecheck、Preview smoke、live benchmark、changelog/readme 检查。按风险选择最小但真实的验证集合。
维护原则 Paper Fucker 是 TUI-first 的论文工作台。新增能力应先回答：用户在哪里看到它、状态在哪里持久化、失败时怎么诊断、Preview 是否能实时看到、导出 gate 如何处理。

三类常见开发模式

TUI 表面

修改首页、模型工作台、环境页、目录选择器或命令面时，先更新 route，再补布局 util 和 TUI 快照/行为测试。

PaperRun 核心

新增 stage、artifact、diagnostic 或事件时，先改 schema/run-store，再让 TUI 与 Preview 读取同一份 snapshot。

论文质量

涉及中国计算机学报格式、实验执行、证据 ledger 或 final gate 时，需要用 live benchmark 生成真实导出再人工检查。

状态输入

新增能力前先明确它读哪些状态。状态必须从持久化事实进入界面，不能只在前端临时拼装。

状态来源典型内容修改原则
PaperRunstage、artifact、diagnostics、source/claim ledger、gate。运行状态先入 run，再由 TUI 和 Preview 读取。
PaperModelInventoryprovider 注册、候选模型、allowlist、主/备用决策模型、阶段策略。可用模型只来自用户允许池；订阅 provider 和自定义 endpoint 统一进入库存。
PaperEnvironmentStatusGPU、编译器、容器、Python、LaTeX、Pandoc、Preview 能力。环境项要区分可用、未配置、可选缺失和阻断缺失。
Preview snapshotdraft、agent tree、token/cost、实验运行、终端摘要、export 状态。Web Monitor 只读，通过 SSE 持续更新。

输出契约

TUI

中文、短句、可诊断。窗口过小、缺模型、缺工作区、缺外部工具时直接给下一步动作。

Preview

显示实时运行事实，不展示占位论文、伪来源或 mock 实验。没有真实 draft 时显示缺失状态。

Export

默认中国计算机学报格式。final export 必须经过 source、claim、citation、license 和 reproduction gate。

Diagnostics

错误返回 code、中文 message、可执行 action 和日志路径。

质量调优

格式中国计算机学报默认输出应包含中文题名、摘要、英文摘要、关键词、引言、相关工作、方法、实验、结论和参考文献。
真实性产品路径不能用伪 locator、mock paper、占位实验或无来源结论。缺网络、密钥、baseline、ablation 或复现材料时必须诊断阻断。
可读性TUI、Preview、导出 Markdown 和 PDF 必须避免文字遮挡、逐字换行、表格溢出和中英文乱码。
可恢复所有长任务要能从 run id 恢复；退出时展示 run id、状态、token/cost 摘要和恢复命令。

故障定位

现象优先检查修复方向
TUI 显示模型未配置model-inventory.json、provider registration、allowlist、首页状态刷新。库存保存后必须同步刷新首页和 PaperRun 创建路径。
PaperRun 创建失败请求 payload、schema 注册、workspace path、run id 唯一性、日志。后端返回结构化诊断，不把 AJV 或数据库错误裸露给用户。
Preview 不刷新SSE token、snapshot publisher、客户端 render helper、只读路由。先用 browser smoke 验证 DOM，再补协议字段和前端渲染测试。
PDF 格式异常Markdown 结构、CJC profile、Pandoc 参数、XeLaTeX/ctex、表格宽度。先修结构化 Markdown，再修导出参数，最后人工查看 PDF。

长链路修改顺序

  1. 先写一条最小端到端路径，保证真实 PaperRun 能创建、更新、预览和导出。
  2. 再补异常路径：无模型、无工作区、provider 失败、schema 失败、实验失败、final gate 失败。
  3. 然后做界面收口：TUI 文案、滚动、终端尺寸、路径截断、Preview 只读和 SSE 更新。
  4. 最后更新 README、开发手册、CHANGELOG，并运行对应检查。
