完整论文生成主链路

顺序函数/模块输入输出不变量
1submitPaperWorkbenchPrompt
routes/paper/index.tsx		首页输入、研究深度、工作目录、材料入口。调用 Paper HTTP API 创建或恢复 run。首页只表达 PaperRun，不触发旧聊天/模式语义。
2normalizeCreatePayload
handlers/paper.ts		TUI/API payload。ResearchIntakeRequest。错误必须转成中文结构化诊断，不能把裸 schema 错误直接给用户。
3createPaperRun
paper/run.ts		研究主题、workspace、code/data/log paths、profile、budget。run 目录、初始 facts、stage graph、snapshot、controller。无模型或无授权模型时阻断；不生成假运行。
4startPaperResearchRun
paper/orchestrator.ts		run store、request、默认 handlers。逐 stage 写 source、artifact、claim、draft、review、export。每个 stage 成功或失败都必须有事件和可恢复状态。
5composeDraftPaper
research/writing/draft.ts		ClaimLedger、LiteratureMap、ExperimentPlan、ExperimentRun、ResultReport、ReviewReport。DraftPaper.v1 和 Markdown 正文。正文只能使用已登记证据；缺证据时写限制或阻断，不写占位结果。
6exportPaperRun
paper/run.ts		run id、export profile、forced 标记。Markdown/LaTeX/PDF/DOCX、manifest、export facts。final export 必须通过 final gate；forced draft 必须保留 failed checks。

文献与 Related Work 链路

函数/模块位置职责不变量
defaultLiteratureDiscoverypaper/orchestrator.ts在 literature stage 生成或接收 LiteratureMap.v1，记录 source、cluster、verification 和 gap。缺网络或缺授权时只能产生 blocked/candidate 诊断，不得伪造 verified source。
defaultClaimLedgerpaper/orchestrator.ts把 literature stage 的 LiteratureMap.v1 带入后续 claim/result/draft 阶段。不能只把文献当作 loose text；必须保留 verification 状态和 locator。
runPaperAuthoringLooppaper/authoring.ts把 LiteratureMap.v1 传给 composeDraftPaper，让 Related Work 由结构化文献图生成。verified source 可以写成 prior work；unverified seed 只能写成候选文献。
literatureEvidenceSummaryresearch/writing/draft.ts渲染 Related Work 的文献表、verification、locator 和缺口说明。未验证来源必须显式标注为候选；不能作为新颖性、领域共识或实验结论支撑。
referencesSummaryresearch/writing/draft.ts生成 References 主文章节。只列入 verified source；未验证 seed 不得进入正式 References。
checkReferencesresearch/verification/checks.ts校验 citation 目标是否存在，并检查是否有 verified paper reference。缺少 verified paper reference 时写入 missing_verified_reference warning；它不阻断 reviewable bundle，但提示尚未达到投稿级引用准备度。
citationTextresearch/writing/draft.ts把正文引用标记渲染为可读标签。主文不输出 cite:* 或 material:code:*，完整 source id 留在附录和 manifest。
paperProseTextresearch/writing/draft.ts把底层 claim 文本中的实现词转换为论文正文表述。正文不应出现 source-range-grounded、source range、final gate、ClaimLedger 等内部写法。
displayMetricName / displayExperimentLabelresearch/writing/draft.ts把 typecheck_pass、baseline:*、ablation:* 转成正文和表格可读名称。协议 id 可以保留在 artifact/manifest，主文只能展示读者可理解的名称。
displayExperimentRole / displayRunStatus / displayEnvironmentresearch/writing/draft.ts把实验角色、运行状态和环境名称转换成论文表格语言。Results 与 Reproducibility 主文不得出现 succeeded、typecheck_pass、baseline:* 这类运行层标识。
refreshDraftPaperForFinalExportpaper/run.tsfinal export 前重新读取最新 LiteratureMap.v1、claims、runs 和 ResultReport，刷新 DraftPaper。用户修复文献或实验后，终稿必须使用最新结构化证据。

实验与代码论文链路

函数位置职责修改时同步
analyzeCodebaseForPaperpaper/code-to-paper.ts扫描代码路径，抽取文件哈希、source range、导出函数、测试和 package scripts。代码语言支持、路径过滤、source range 测试。
planExperimentsresearch/experiments/planning.ts把代码入口和用户协议转成 proposed、baseline、ablation、container reproduction 计划。实验角色、指标、GPU/容器资源预算、fallback 策略。
runHostExplorationresearch/experiments/runner.ts受控执行 host 命令，记录 exit code、耗时、stdout/stderr 摘要和指标。超时、环境变量白名单、输出截断、Windows 路径。
runPaperRunExperimentProtocolpaper/run.ts从 run 中读取协议，执行 proposed/baseline/ablation/container，并写回 ResultReport。HTTP endpoint、TUI 按钮、Preview snapshot、paperrun-execution test。
experimentProtocolFromWorkspacePackageJsonpaper/run.ts重跑前重新扫描当前 workspace 的 package scripts，支持用户补齐 starter 后升级为真实协议。starter-rerun benchmark，避免继续跑旧 placeholder 协议。
analyzeExperimentResultsresearch/experiments/analysis.ts比较主指标、baseline、ablation 和 host/container 一致性，决定 final claim 是否允许。ResultReport schema、final gate、Results 文案。

Preview 与监控链路

函数/文件职责常见错误验收
createPaperRunLivePreviewSnapshot
paper/run.ts		把 run facts 汇总为 PreviewSnapshot.v1。新增 artifact 后忘记暴露到 monitor，Web 监控台看不到。检查 snapshot JSON 与 Preview DOM。
PreviewRenderQueue.replaceSnapshot
packages/preview/src/render-queue.ts		推送最新 snapshot，取消旧渲染任务。只更新 HTTP snapshot，忘记 SSE。preview test 的 SSE 用例。
renderGate
packages/preview/src/client.js		展示 gate、机器环境、实验建议、实验运行和终端 trace。模板字符串语法错误会导致整页只剩静态 shell。node --check packages/preview/src/client.js 与浏览器 smoke。
renderTraceExcerpt
packages/preview/src/client.js		默认展开 stdout/stderr 摘要，让用户能直接判断实验为什么通过或失败。只在 JSON 中有 trace，DOM 不显示，用户仍看不到终端证据。浏览器 smoke 断言 DOM 包含 stdout 摘要。
startPreviewServer
packages/preview/src/server.ts		提供 token-protected snapshot、SSE、静态资源和只读拦截。写请求未拒绝、token 漏校验、长连接超时。packages/preview test 与 live-preview-browser-smoke.ps1。

模型与运行权限链路

函数/模块职责规则
loadPaperModelInventory读取本机模型库存、provider 注册、allowlist、主/备用决策模型。候选模型不是可用模型；只有 allowlist 允许进入路由。
savePaperModelInventory保存用户已注册 provider 和模型选择。保存后 TUI 首页和 run 创建必须读同一份库存。
routePaperModel根据 stage、预算、隐私、工具需求选择模型。用户强制指定优先；不可用时返回 blocked/pause，不静默降级。
PaperModelWorkbenchPage全屏模型工作台。只展示已注册 provider；所有模型页多选进入候选池，主/备用模型只能从候选池选。

定位问题的最短路径

论文不完整先看 DraftPaper.v1、ResultReport.v1、BlockingReport.v1，再看 composeDraftPaper 是否读到了最新 artifact。
实验没跑看 ExperimentProtocol.v1、package scripts、runPaperRunExperimentProtocol 返回的 terminal_traces。
Preview 空白先跑 node --check packages/preview/src/client.js，再看浏览器 smoke 的 DOM failure 文件。
final 不生成看 BlockingReport.v1、final_gate、export_state.failed_checks，不要直接改 export 绕过 gate。
