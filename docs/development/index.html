Paper Fucker 开发手册

这是一套面向维护者的多页 HTML 手册，说明产品入口、架构边界、PaperRun 状态机、模型工作台、实验执行、实时监控、导出 gate 和常见修改路径。

中文优先 PaperRun-first 开发态 0.13.x MPL-2.0

阅读路线

使用入口给开发者快速跑通 TUI、模型、工作区、PaperRun、Preview、导出和恢复。 开发指南按产品链路定位模块、状态事实、入口层、验证层和质量调优点。 架构说明 TUI、Paper Core、HTTP API、Preview、research tools、schemas 和 run storage 的边界。 PaperRun 流程解释 intake、stage graph、artifact、ledger、diagnostics、controller 和 SSE 事件。 关键函数索引按真实调用链定位 create、orchestrator、writing、experiment runner、Preview 和模型路由。 修改手册新增 stage、artifact、TUI 页面、Preview 字段、模型策略和测试时的文件清单。

系统形态

主入口

中文 TUI 是用户主入口。用户输入主题、代码、论文材料、数据或实验日志后，系统创建可恢复、可审查的 PaperRun。

核心状态

PaperRun 持有 intake、stage graph、events、source ledger、claim ledger、agent tree、diagnostics、preview/export 和 controller。

质量边界

final export 只在 source、claim、citation、license 和 reproduction gate 通过后生成；forced draft 必须显式保留失败项。

运行目录

默认写入 ~/.paper_fucker/runs/<run-id>。用户选择工作区后，才使用工作区内的运行目录。

核心流程

1. TUI 收集主题和材料 2. API 规范化 intake 3. Paper Core 创建 run 4. Agent Team 执行 stage 5. Preview SSE 实时更新 6. Gate 通过后导出 
home.tsx
  -> createPaperRunFromPrompt()
  -> POST /paper/runs
  -> createPaperRun()
  -> createResearchRun()
  -> startPaperResearchRun()
  -> publishPaperRunSnapshot()
  -> previewPaperRun() / exportPaperRun()

维护原则

  • 用户可见体验以 Paper Fucker 和 PaperRun 为主语；底层包名只在开发文档、路径和代码引用中出现。
  • 模型只能来自用户注册并允许的 provider/model 池；候选模型和可用模型必须分开。
  • 代码型论文必须把本地代码 source range 写入 source ledger，并绑定到 ClaimLedger。
  • 实验型论文必须写入 host/container reproduction 证据；缺失时 final export 阻断。
  • 新增功能要同步 TUI、HTTP API、PaperRun artifact、Preview、测试、README 或开发手册。
