# 数据库设计文档

## 1. 概述

IntelliGen 当前使用 **MySQL 8.4** 作为主数据库，活跃后端位于 `packages/api`，ORM 为 SQLAlchemy 2.0，迁移由 Alembic 管理。

当前数据库既承载业务主表，也承载生成断点与审计日志数据：

- 用户与权限
- 会话、附件、任务
- 任务执行断点与章节 checkpoint
- 操作审计日志

## 3. 主要关系

| 关系 | 说明 |
| --- | --- |
| `users` 1 -> N `sessions` | 一个用户可拥有多个会话 |
| `users` 1 -> N `files` | 一个用户可拥有多个文件 |
| `sessions` 1 -> N `generate_tasks` | 一个会话可触发多个生成任务 |
| `generate_tasks` 1 -> N `generate_task_files` | 一个任务可关联多个输入文件快照 |
| `sessions` 1 -> N `files`（通过 `sourceSessionId`） | 会话附件从文件表中筛出 |
| `task_executions` / `section_checkpoints` -> `task_id` | 生成续跑和章节 checkpoint 的执行态数据 |

## 4. 迁移与初始化

### 4.1 环境配置

后端数据库连接通过 `packages/api/.env` 配置，核心变量包括：

- `DB_HOST`
- `DB_PORT`
- `DB_NAME`
- `DB_USERNAME`
- `DB_PASSWORD`

### 4.2 迁移命令

```bash
cd packages/api
alembic upgrade head
```

Alembic 入口位于：

- `packages/api/alembic/`
- `packages/api/alembic/env.py`

## 5. 设计说明

1. 业务主表大量沿用了历史 camelCase 列名，以保证兼容性。
2. 生成断点表 `task_executions` / `section_checkpoints` 沿用 snake_case 结构，主要服务于续跑与章节恢复。
3. `generate_tasks.resultMarkdown` 存放最终 Markdown，`errorMessage` 只保留清洗后的错误信息。
4. `files.sourceSessionId` 用于区分普通用户文件与挂到会话下的附件。
5. 审计日志通过 `requestId` / `traceId` 串联请求链路，便于回溯接口行为。
