# 前后端交互说明文档

## 1. 概述

IntelliGen 当前采用标准前后端分离架构：

- **前端**：`packages/web`，Vue 3 + Vite + Pinia
- **后端**：`packages/api`，FastAPI + SQLAlchemy
- **数据层**：MySQL 8.4
- **生成与检索能力**：作为后端内部模块存在，不再以独立模型服务对外暴露

本文档描述当前前后端如何协作，包括认证、工作区加载、任务创建、实时进度、结果预览与异常处理。

## 2. 当前系统边界

### 2.1 前端边界

前端采用 feature-first 结构：

```text
packages/web/src/
├── app/          # 启动、router、全局注入
├── features/     # auth / admin / workspace
├── shared/       # api / utils / ui / stores
└── assets/
```

前端主要负责：

- 登录态承接与页面路由
- 会话 / 附件 / 任务的工作区交互
- SSE 进度订阅与失败回退轮询
- 报告预览、引用点击、证据侧栏与下载触发

### 2.2 后端边界

后端采用平台层 + 领域模块结构：

```text
packages/api/app/
├── platform/     # config, db, logging, middleware, security
└── modules/
    ├── auth/
    ├── admin/
    ├── workspace/
    └── generation/
```

后端负责：

- 鉴权、权限校验、用户审核
- 会话、文件、任务的持久化与聚合查询
- 生成流程编排、检索、引用注册、章节重生成
- 审计日志、错误清洗、任务进度发布

## 3. 通信约定

### 3.1 传输方式

- 普通接口：HTTP + JSON
- 文件上传：`multipart/form-data`
- 任务实时进度：SSE（`text/event-stream`）

### 3.2 统一返回格式

普通接口统一返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

### 3.3 认证方式

当前主路径为 **Cookie 鉴权**：

1. 前端调用 `POST /auth/login`
2. 后端校验成功后写入 `access_token` httpOnly Cookie
3. 浏览器后续请求自动携带 Cookie
4. 后端从 Cookie 中解析 JWT；若无 Cookie，再尝试 `Authorization: Bearer <token>`

说明：

- 前端不再以 `localStorage` 作为主认证存储。
- 对于脚本、调试工具、测试客户端，可继续使用 Bearer Token 兼容模式。

## 4. 主要交互流程

### 4.1 登录与初始化

```text
前端 -> POST /auth/login
前端 <- Set-Cookie: access_token=...
前端 -> GET /auth/userinfo
前端 -> GET /sessions
```

登录成功后，前端根据用户角色进入普通工作区或管理员功能区。

### 4.2 工作区加载

当用户进入某个会话时：

```text
前端 -> GET /sessions/{sessionId}/workspace
后端 <- { session, tasks, attachments }
```

该接口是工作区首屏的聚合入口，前端据此恢复：

- 当前会话信息
- 已有任务列表
- 已上传附件列表

### 4.3 附件上传

附件有两种进入方式：

1. 上传到个人文件区：`POST /files/upload`
2. 直接上传并挂到会话：`POST /sessions/{sessionId}/attachments`

后端会返回统一的文件元数据：

- `fileId`
- `fileName`
- `fileUrl`
- `fileType`
- `sourceSessionId`

### 4.4 创建任务与实时进度

创建任务：

```text
前端 -> POST /sessions/{sessionId}/tasks
```

任务创建成功后，前端优先使用：

```text
GET /tasks/{taskId}/stream
```

订阅实时进度；若 SSE 不可用，则回退到周期性 `GET /tasks/{taskId}` 轮询。

前端关注的核心状态字段：

- `status`
- `progress`
- `currentSection`
- `totalSections`
- `retryCount`
- `errorMessage`
- `errorCategory`

### 4.5 报告预览与证据交互

任务完成后，后端返回：

- `resultMarkdown`
- 任务关联文件信息
- 引用编号与参考文献段落

前端在工作区预览侧：

1. 解析 Markdown 与参考文献
2. 把 `[N]` 引用转换为可点击证据入口
3. 在证据侧栏中展示引用详情、跳转与高亮

### 4.6 失败重试与章节重生成

失败任务可通过：

```text
POST /tasks/{taskId}/retry
```

重新入队。

已完成任务的单个章节可通过：

```text
POST /tasks/{taskId}/sections/{sectionIndex}/regenerate
```

配合可选 `customPrompt` 做定向重生成。后端会在已有全文、邻接上下文与引用信息基础上构建 grounded prompt。

### 4.7 下载

当前前后端协作的下载格式为：

- `md`
- `docx`

调用入口：

```text
GET /tasks/{taskId}/download?format=md|docx
```

## 5. 错误处理与可观测性

### 5.1 常见错误语义

- `401`：未登录或登录过期
- `403`：账号未审核 / 已禁用 / 管理员权限不足
- `404`：资源不存在
- `500/503`：生成链路或外部能力不可用，返回已清洗错误信息

### 5.2 可观测性字段

后端通过中间件和结构化日志补充以下上下文：

- `request_id`
- `trace_id`
- `user_id`

任务失败时，前端可使用：

- `errorMessage`
- `errorCategory`

做更精细的提示，而不直接暴露底层异常细节。

## 6. 当前协作原则

1. **前端只依赖统一 FastAPI 接口，不直接调用外部模型服务。**
2. **工作区以聚合接口和任务状态接口为主，不在前端拼接业务状态。**
3. **实时进度优先 SSE，轮询仅作为降级路径。**
4. **鉴权以 Cookie 为主，Bearer 为兼容调试路径。**
5. **历史双后端交互文档仅保留在 `docs/archive/`，不用于当前开发。**
