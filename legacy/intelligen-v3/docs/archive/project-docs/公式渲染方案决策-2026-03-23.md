# 公式渲染方案决策 - 2026-03-23

## 当前结论

围绕报告中的公式展示与导出问题，当前冻结两条决策：

1. 网页内报告阅读视图  
   采用 `B 方案`，即 `KaTeX 渲染 + 公式预处理 + 优雅降级`。

2. DOCX 导出中的公式处理  
   已从最初的“纯图片视觉正确”升级为 `混合方案`：
   - `Word 原生公式优先`
   - `复杂公式图片兜底`
   - `坏公式文本降级`

当前不直接升级到完整的高阶 `C 方案`。只有在混合方案落地后，真实报告里仍持续出现明显残留问题时，才继续升级。

## 一、网页报告公式渲染决策

### 目标

在不修改后端协议、不修改模型服务输出结构的前提下，提升网页内报告阅读视图对常见科研公式的渲染稳定性。

### 采用方案

- `KaTeX` 负责公式渲染
- 增加公式预处理层
- 对坏公式做优雅降级
- 保持现有 Markdown 报告阅读体验不被破坏

### 适用范围

- 行内公式：`$...$`
- 块级公式：`$$...$$`
- 括号公式：`\(...\)`、`\[...\]`
- 常见科研表达：
  - 上标 / 下标
  - 分式
  - 希腊字母
  - `\text{}`
  - `\sim`
  - `\tan\delta`
  - `\varepsilon_r`
  - `${}^{1}\text{H-NMR}`
  - `${}^{29}\text{Si-NMR}`

### 本次不做

- 不修改数据库字段
- 不修改后端返回结构
- 不要求模型服务直接输出 HTML
- 不在网页渲染阶段处理 DOCX 的可编辑公式对象

## 二、DOCX 公式导出决策

### 背景变化

最初的 DOCX `B 方案` 采用了“图片优先”的视觉正确路线。  
该路线能解决“源码暴露”问题，但在真实 Word 文档里仍然存在这些体验缺陷：

- 行内公式与正文基线不够自然
- 部分公式有明显“贴图感”
- 表格中的公式图片观感不够高级

因此，从 `2026-03-24` 起，DOCX 导出路线升级为混合方案。

### 当前采用方案

DOCX 公式导出采用 `混合方案`：

1. 标准常见公式优先转为 `Word 原生公式`
2. 复杂或不支持的公式回退为图片
3. 明显损坏的公式继续降级为文本

### 为什么这样选

- 比“纯图片”更自然，成品感更好
- 比“全量可编辑公式”风险更低
- 更适合当前项目阶段
- 后续如果仍需升级到完整高阶方案，当前的预处理、识别、分流逻辑仍可复用

### 当前分流原则

- 行内常见公式：优先走 Word 原生公式
- 块级常见公式：优先走 Word 原生公式
- 表格内常见公式：优先走 Word 原生公式
- 特殊环境、复杂结构、转换失败：图片兜底
- 坏公式、不闭合公式：文本降级

### 当前不做

- 不追求所有公式都变成 Word 可编辑对象
- 不追求一次性覆盖所有非常规 LaTeX 写法
- 不把 Markdown 下载当成成品渲染出口

## 三、Markdown 下载的定位

Markdown 下载继续保留，但定位明确为：

- 原始研究源码下载
- 调试与归档用途

不将 Markdown 下载视为“最终成品报告”的主要交付形式，也不要求它像网页报告一样天然完成公式可视化渲染。

## 四、执行约束

从本文件更新开始，公式相关问题按以下顺序推进：

1. 先完成网页报告公式渲染的 `B 方案`
2. 再完成 DOCX 公式导出的混合方案
3. 用真实报告样本验收
4. 只有在上述方案仍有明显残留问题时，才升级到更重的高阶方案

## 五、后续升级条件

如果后续真实报告中持续出现以下问题，可继续升级：

- 常见公式在 Word 中仍大面积显示异常
- 表格内公式仍明显影响阅读
- 出现明确的“必须在 Word 中继续编辑公式”需求
- 当前混合方案无法满足正式交付标准
