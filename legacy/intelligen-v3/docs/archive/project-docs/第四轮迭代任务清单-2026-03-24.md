# 第四轮迭代任务清单（2026-03-24）

## 迭代目标

本轮迭代按以下优先级冻结执行：

1. 先做报告成品化增强
2. 再做前端整站体验增强
3. 最后做部署、监控与其余工程化增强

## 执行规则

- 不跨阶段跳步。上一阶段未验收通过前，不进入下一阶段。
- 每一步都必须同时满足：功能落地、效果达到验收标准、关键测试通过、真实样本验证通过。
- 与正式开发文档主任务冲突时，以已完成主任务为前提，只做增强，不回退主链路能力。
- 新增增强项如需进入执行，先单独成文，再决定是否纳入本清单。

## 第一阶段：报告成品化增强

### Step 1. DOCX 报告视觉体系收口 `[已完成]`

目标：
- 先把导出文档的基础页面样式、标题、段落、表格、列表、代码块统一成正式报告风格。

主要工作内容：
- 固定 A4 页面尺寸、页边距、正文排版、段落间距和首行缩进。
- 收口标题层级、列表缩进、引用块、代码块、表格表头与边框样式。
- 让基础 DOCX 结果具备正式交付文档的视觉一致性。

验收标准：
- DOCX 导出视觉风格统一。
- 常见 Markdown 结构在 Word 中排版稳定。
- 构建和测试通过。

### Step 2. 封面与基础元信息

目标：
- 让导出的报告具备正式封面、标题区和基础元信息。

主要工作内容：
- 增加报告标题、导出时间、会话标题、模板名称等基础信息。
- 设计统一封面结构与首页视觉层级。
- 明确封面、正文、附录的区隔。

验收标准：
- 导出的 DOCX 打开后具备完整封面和基础信息区。
- 不再是“直接从正文开始”的技术导出稿。

### Step 3. 目录与章节结构增强

目标：
- 让长报告具备更好的可阅读性和跳读能力。

主要工作内容：
- 基于标题层级生成目录。
- 规范章节编号与多级标题结构。
- 收口目录与正文标题的映射关系。

验收标准：
- 中长篇报告导出后可快速定位章节。
- 章节层级稳定，不出现混乱编号。

### Step 4. 页眉、页脚与页码增强

目标：
- 提升文档完整度和正式感。

主要工作内容：
- 增加页眉、页脚、页码。
- 明确首页与正文页的页眉页脚策略。
- 收口页眉页脚与封面、目录的关系。

验收标准：
- 导出文档具备稳定的页眉页脚和页码样式。

### Step 5. 复杂格式稳定性增强

目标：
- 继续消灭报告中的格式暴露和结构混乱问题。

主要工作内容：
- 收口公式、粗体、列表、换行、引用、表格混排场景。
- 保证网页报告与 DOCX 导出在结构上尽量一致。
- 处理真实报告中的边界样本。

验收标准：
- 不再出现明显的 `**`、`<br>`、错位列表、公式裸露等问题。
- 常见复杂样本可以稳定导出。

### Step 6. 真实样本回归验收

目标：
- 用真实会话和真实报告样本确认“成品化增强”不是只对测试样例有效。

主要工作内容：
- 选取多份真实报告做网页与 DOCX 双侧回归。
- 记录残留问题并分类。
- 冻结本阶段验收结论。

验收标准：
- 真实样本通过率达到可交付水平。
- 阶段内关键问题闭环处理完成。

## 第二阶段：前端整站体验增强

### Step 7. 应用壳统一

目标：
- 统一整站导航、外壳布局和页面层级。

主要工作内容：
- 收口工作台、管理台、登录页的整体骨架。
- 统一边栏、顶部栏、页面容器和阅读区结构。
- 消除“像多个页面拼出来”的割裂感。

验收标准：
- 全站主要页面在布局语言上统一。
- 页面层级清晰，不再依赖临时样式拼接。

### Step 8. 工作台主界面体验增强

目标：
- 让工作台真正具备“多轮研究助手”的清晰体验，而不是只靠临时提示驱动。

主要工作内容：
- 收口会话历史、多轮任务时间线、报告阅读、输入区和状态区之间的关系。
- 增强报告查看、全屏阅读、下载、复制与切换视图的体验。
- 提升工作台在真实研究流程中的可追溯性和连续性。

验收标准：
- 多轮研究记录清晰可追溯。
- 报告查看和任务状态切换顺滑。
- 用户在工作台内能明确理解当前任务与历史任务关系。

### Step 9. 管理台体验增强

目标：
- 让管理端更像正式后台系统，而不是把功能堆在一起。

主要工作内容：
- 收口审核中心、模板库、概览区的结构。
- 优化管理列表、筛选、分页、空状态和操作反馈。
- 统一管理台的视觉系统和交互规则。

验收标准：
- 管理台结构清晰，主次分明。
- 管理任务可快速完成，不再依赖用户猜测。

### Step 10. 设计系统与视觉语言统一

目标：
- 建立贯穿登录页、工作台、管理台的统一视觉语言。

主要工作内容：
- 收口颜色、圆角、阴影、按钮、表单、标签和状态样式。
- 统一字体层级、间距系统和组件规范。
- 减少页面间风格漂移。

验收标准：
- 全站观感统一，组件风格一致。

### Step 11. 响应式与可用性增强

目标：
- 提升桌面端和较小视窗下的可用性。

主要工作内容：
- 收口工作台、管理台在不同窗口尺寸下的布局。
- 增强滚动区、悬浮层、弹层、快捷操作和空状态。
- 优化可读性、可点击性和交互连续性。

验收标准：
- 常见分辨率下布局稳定。
- 关键操作路径不拥挤、不遮挡。

## 第三阶段：部署、监控与其余增强

### Step 12. 部署与运行标准化

目标：
- 固化当前已跑通的前后端部署链路。

主要工作内容：
- 收口前端静态部署、后端 jar 部署、nginx 代理和后端环境变量。
- 固化发布、重启和回滚步骤。
- 明确本地开发与服务器联调的标准流程。

验收标准：
- 发布链路清晰，重复部署成本低。

### Step 13. 网关与访问层增强

目标：
- 提升公网访问的稳定性与一致性。

主要工作内容：
- 收口 `/backend` 代理、静态资源缓存、上传大小、错误页等配置。
- 为后续域名、HTTPS、统一入口做准备。

验收标准：
- 前端、后端、文件访问链路在公网入口下稳定可用。

### Step 14. 监控、日志、备份与回滚

目标：
- 降低线上问题排查和恢复成本。

主要工作内容：
- 收口后端日志输出、nginx 日志、关键错误追踪。
- 明确备份、回滚和重启策略。

验收标准：
- 常见线上问题可快速定位和恢复。

### Step 15. 测试与发布基线增强

目标：
- 为后续迭代提供稳定的质量门槛。

主要工作内容：
- 补充更完整的回归测试点。
- 固化发布前检查项。
- 形成可重复执行的验收清单。

验收标准：
- 后续迭代不会因为缺少基线而频繁返工。

## 推荐执行节奏

1. 先完成第一阶段所有步骤。
2. 第一阶段验收通过后，进入第二阶段。
3. 第二阶段收口整站体验后，再处理第三阶段的部署与工程化增强。
