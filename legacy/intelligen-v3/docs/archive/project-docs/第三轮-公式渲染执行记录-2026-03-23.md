# 第三轮-公式渲染执行记录（2026-03-23）

## 背景

在报告阅读视图中，出现了 `${}^{1}\text{H-NMR}$`、`\frac{}`、`\delta`、`\varepsilon_r` 等公式源码直接暴露的问题，影响报告成品观感。

## 本次决策

- 采用 `B 方案`：`KaTeX 渲染 + 公式预处理 + 优雅降级`
- 暂不升级到 `C 方案`
- 如果后续真实报告中仍持续出现明显公式残留，再升级到 `C 方案`

## 本次落地内容

1. 在前端引入 `katex`
2. 在 `renderReportMarkdown()` 中扩展渲染链路：
   - 规范化文档源文本
   - 保护代码块与行内代码
   - 提取块级与行内公式
   - 先走 Markdown 渲染
   - 再用 KaTeX 回填公式
   - 对非法公式做降级显示
3. 为报告阅读视图补充 KaTeX 展示样式
4. 增加覆盖公式、表格、代码块、坏公式降级的测试

## 本次额外修复

在实现公式渲染时，顺手修复了一个隐藏问题：

- 占位符恢复阶段原先使用 `replaceAll(search, replacement)`，当代码片段里出现 ``$` `` 这类字符串时，会触发 JavaScript 的替换语义，导致行内代码被串改
- 现已改为纯字面量恢复，不再让代码片段在恢复阶段被错误展开

## 验证结果

- `npm run test` 通过
- `npm run build` 通过

## 当前能力边界

- 标准 LaTeX 行内/块级公式已支持
- 常见科研报告中的上标、下标、分式、希腊字母、`\text{}` 这类表达已覆盖
- 代码块与行内代码不会被误当成公式
- 明显损坏的公式不会拖垮整篇报告，会优雅降级成可读文本

## 后续升级条件

如果后续仍频繁出现以下情况，可以再升级到 `C 方案`：

- 更复杂的表格混排公式仍残留源码
- 非标准 LaTeX 写法无法稳定渲染
- 特殊科研公式或更重的公式环境需要更强兼容层
