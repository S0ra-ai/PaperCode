## 3. 已确认的关键差异

### 3.1 模板字段统一为 `templateFileId`

当前代码已经统一按下面这套语义执行：
- 会话创建时使用 `templateFileId`
- `sessions` 表里保存的是 `templateFileId`
- 前端选择模板时传的也是 `templateFileId`
- `GET /templates` 返回的也是 `templateFileId`

结论：
- 早期“`templateId` 和 `templateFileId` 混用”的问题，在当前代码里已经不再是现存问题

### 3.2 模板文件类型有明确限制

这是本轮联调实测确认的真实行为，正式文档里没有强调到这个粒度。

当前后端要求：
- 管理员创建模板时，模板文件只接受 `docx` 或 `pdf`
- 如果上传的是其他类型，例如 `md`，`POST /admin/templates` 会返回 `400`

这条规则来自当前代码真实实现，不是联调时的偶发问题。

### 3.3 会话删除多了一层任务保护

正式开发文档里主要描述了会话本身，但当前后端实现已经补了更严格的删除保护：
- 如果会话下已经存在任务，删除会话会被拦截
- 后端还加了 `flush()` 和数据库外键异常兜底，避免并发或竞态情况下直接抛底层错误

结论：
- 当前真实行为是“有任务的会话不可删”

### 3.4 历史任务列表和任务详情增加了降级行为

当前后端实现比正式文档更稳一些：
- `GET /sessions/{sessionId}/tasks` 在模型服务异常时，会优先返回本地已有任务数据，而不是整页失败
- `GET /tasks/{taskId}` 在任务状态刷新失败时，也会尽量保留本地状态，不把模型服务波动直接放大成整页不可用

结论：
- 当前任务查询链路比正式文档描述得更“抗模型服务故障”

### 3.5 任务创建的失败语义被收紧

当前代码真实行为：
- 先在本地创建任务草稿
- 再调用外部模型服务创建远程任务
- 如果远程成功、但本地同步失败，本地任务会被标记为 `failed`
- 后端会记录日志，避免任务状态悬空

仍然存在的边界风险：
- 外部模型服务如果已经成功创建了任务，而本地同步失败，外部侧仍可能留下孤儿任务
- 这是当前架构边界问题，不是前后端联调问题

### 3.6 前端页面行为比正式文档多了几层保护

当前前端已经补上的真实行为：
- 工作台任务表单按会话隔离，不同会话不会串草稿
- 创建任务过程中切换会话，不会把轮询结果串写到错误会话
- 管理员审核页的通过/驳回按钮有行级 loading 与禁用保护
- 驳回弹窗如果取消，不会继续提交审核请求
- 路由守卫在读取 `localStorage.userInfo` 时有 JSON 解析兜底，坏数据不会直接导致白屏

这些都属于当前代码真实行为，正式文档里没有完整覆盖。

## 4. 正式文档未覆盖但当前代码已存在的接口/能力

### 4.1 文件详情接口

- `GET /files/{fileId}`
- 仅文件所属用户可访问

### 4.2 文件删除接口

- `DELETE /files/{fileId}`
- 删除前会做引用校验
- 如果文件仍被模板、会话模板或任务附件引用，会拒绝删除

### 4.3 管理员模板创建接口

- `POST /admin/templates`
- 需要管理员权限
- 使用已上传文件的 `fileId` 创建模板记录

### 4.4 管理员模板删除接口

- `DELETE /admin/templates/{templateId}`
- 需要管理员权限

### 4.5 健康检查接口

- `GET /api/health`
- 用于本地启动验证、部署探活、联调排查

### 4.6 上传文件静态访问路径

- `/uploads/**`
- 当前后端会把上传文件映射成可访问 URL，用于后续任务链路消费

### 4.7 管理员启动引导能力

当前代码支持通过环境变量自动初始化管理员账号：
- `ADMIN_BOOTSTRAP_USERNAME`
- `ADMIN_BOOTSTRAP_PASSWORD`
- `ADMIN_BOOTSTRAP_NICKNAME`
- `ADMIN_BOOTSTRAP_EMAIL`

这属于工程化辅助能力，正式开发文档没有展开写。

### 4.8 模型服务密钥环境变量兼容

当前代码兼容两种写法：
- `MODEL_SERVICE_SECRET`
- `MODEL_SERVICE_SECRET_KEY`

这是为了兼容旧配置。
