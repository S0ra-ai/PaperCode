# IntelliGen 第二轮收官与第三轮候选清单

更新时间：2026-03-22

## 1. 第二轮完成结论

第二轮可以视为完成。

这一轮已经把项目从“前后端主链路可联调”推进到“可以稳定本地开发、可以做对外演示、可以继续迭代”的状态。当前前后端的核心链路、模型联通边界、测试基础、启动方式和关键页面结构都已经收口。

## 2. 第二轮已完成项

### 已完成的文档延伸项

1. 工作台、登录页、管理员页完成了第二轮交互与结构收口。
2. 模型服务接入边界已经按真实联调结果收口。
3. 可演示版本验收已经完成，主链路可以真实跑通到模型服务。

### 已完成的纯扩展项

1. 前端测试基础设施已补齐并已接入 `vitest`。
2. 后端关键 service 测试已补到模板、文件删除保护、模型服务异常分支。
3. 本地联调环境变量样例、启动脚本、启动说明已固定。
4. 工作台旧隐藏模板和未使用组件已清理，页面与容器边界更清楚。
5. 第二轮的真实行为、验收结果、联调边界已经沉淀为补充文档。

## 3. 当前稳定基线

当前默认可工作的本地开发基线是：

1. 前端本地运行。
2. 后端本地运行。
3. 数据库通过 SSH 隧道连接远程 MySQL。
4. 模型服务使用远程 `http://43.153.41.145:8081/api`。

当前已验证通过的能力包括：

1. 注册、审核、登录。
2. 文件上传、模板创建、模板选择。
3. 会话创建、任务提交、任务轮询。
4. 纯文本任务可成功进入模型服务并进入 `processing`。
5. 前端 `npm test`、`npm run build` 和后端 `mvn test -q` 可以作为当前基线验证命令。

## 4. 当前仍然存在的边界

这些不是第二轮遗漏，而是当前系统的真实边界：

1. 纯文本任务链已验证联通，但“本地附件/本地模板 -> 远程模型服务读取文件”的完整链路仍依赖公网可访问的 `FILE_BASE_URL`。
2. 当前工作台已经从“大杂烩布局”拆成了聊天式主舞台，但整站视觉语言仍然可以继续做更彻底的整站重构。
3. 管理员端已经比第一轮清晰，但如果要达到更强的企业后台感，仍然值得继续重做信息架构。
4. 当前自动化测试以关键逻辑和 service 风险分支为主，页面级测试和更高层集成测试还可以继续扩展。

## 5. 第三轮优先候选项

建议第三轮优先级按下面顺序考虑：

1. 完成“公网文件访问链路”收口。
说明：把 `FILE_BASE_URL` 改成模型服务可访问地址，真正打通“附件/模板参与研究”的完整闭环。

2. 做整站前端重构。
说明：不是继续局部修页面，而是把登录页、工作台、管理员页统一成一套新的产品骨架和视觉系统。

3. 做结果展示体验升级。
说明：把 `resultMarkdown` 展示得更像正式回答，而不是当前偏原始的任务结果回显。

4. 扩充前端页面级测试与关键流集成测试。
说明：覆盖聊天式工作台、管理员审核链路、模板管理链路。

5. 扩充后端任务同步与模型异常恢复策略。
说明：继续补任务状态回收、重试、超时和更细的错误分层。

## 6. 第三轮建议起点

如果第三轮仍然以“产品闭环”为最高优先级，建议从下面两条里选一条开始：

1. 先做“公网文件访问链路”，优先补完整业务闭环。
2. 先做“整站前端重构”，优先补产品观感和使用体验。

如果以当前你的反馈为准，更建议优先做第 2 条，也就是先做整站前端重构。
