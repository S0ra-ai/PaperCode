# IntelliGen 前后端开发执行清单

更新时间：2026-03-19

## 1. 文档定位

本文件是 IntelliGen 当前阶段前后端开发的执行基线，用来统一以下内容：

- 当前开发范围
- 任务优先级
- 每一步的执行顺序
- 每一步的完成标准
- 中途遇到阻塞时的处理方式

后续若无新的明确指令，默认严格按照本文件顺序推进开发，不随意跳级，不将 `model_strategy` 纳入本轮开发范围。

## 2. 当前范围冻结

### 2.1 本轮开发范围

- 前端：`intelligen-frontend`
- 后端：`intelligen-backend`

### 2.2 本轮不开发范围

- `model_strategy` 内部实现
- 模型策略服务算法、报告生成逻辑、Embedding/RAG 相关实现

### 2.3 外部依赖处理原则

- `model_strategy` 视为外部服务
- 我们只关心后端如何调用它，以及前端如何消费后端统一返回的数据
- 如果端到端联调依赖模型服务可用，则在后端层明确错误提示和降级行为

## 3. 当前项目状态判断

截至 2026-03-19，项目状态如下：

- 前端已经有登录/注册、工作台、管理员审核页三块主界面
- 前端 `npm run build` 已通过
- 后端已实现认证、用户审核、文件、模板、会话、任务等主接口
- 后端 `mvn test -q` 已通过
- 后端存在契约测试，说明接口主链路已有基础约束
- 当前整体更接近“可联调 MVP”，不是最终交付版本

## 4. 后续执行总原则

### 4.1 顺序原则

- 先解决联调基础，再收紧契约和校验，再补状态与页面闭环，最后做联调验收和测试文档
- 未完成 `P0` 前，不进入 `P1`
- 未完成主链路联调验收前，不进入扩展功能

### 4.2 变更原则

- 只修改当前任务所需文件
- 不主动改动 `model_strategy`
- 不因为“顺手”而超范围重构
- 发现文档与代码不一致时，以“当前代码真实行为 + 本文件冻结决策”为准

### 4.3 阻塞处理原则

如果遇到以下情况，需要先记录并暂停当前子步骤，再决定是否继续：

- 依赖外部凭证或外部服务不可用
- 当前实现与用户已有本地改动直接冲突
- 继续修改会造成前后端契约大改
- 当前问题需要用户决定产品取舍

### 4.4 完成定义

每个步骤完成，至少要满足：

- 代码已修改
- 基本验证已执行
- 与本步骤相关的文档或清单已同步
- 没有留下未说明的已知阻塞

## 5. 推荐本地联调基线

本项目推荐采用以下本地联调方案：

### 5.1 前端

- 开发端口：`5173`
- API 基地址通过 `VITE_API_BASE_URL` 配置
- 默认指向：`http://127.0.0.1:8080`

### 5.2 后端

- 服务端口：`8080`
- 数据库：MySQL
- 文件访问基地址：`FILE_BASE_URL`
- 模型服务地址：`MODEL_SERVICE_BASE_URL`

### 5.3 推荐决策

本轮优先推荐：

- 后端补 CORS，允许本地前端开发地址访问
- 前端继续保留 `VITE_API_BASE_URL` 直连后端

原因：

- 这样更接近生产接口形态
- 前端无需额外维护代理规则
- 后续环境切换只需改环境变量

### 5.4 当前固定本地启动方式

前端：

```bash
cd intelligen-frontend
npm run dev
```

后端：

```bash
cd intelligen-backend
mvn spring-boot:run
```

本地关键环境变量：

- 前端：`VITE_API_BASE_URL=http://127.0.0.1:8080`
- 后端：`CORS_ALLOWED_ORIGINS=http://127.0.0.1:5173,http://localhost:5173`
- 后端：`FILE_BASE_URL=http://127.0.0.1:8080`
- 后端：`MODEL_SERVICE_BASE_URL`、`MODEL_SERVICE_APP_ID`、`MODEL_SERVICE_SECRET` 按联调环境配置

## Step 1. 打通本地前后端联调基础配置

### 目标

### 子步骤

- [x] 确认前端当前 API 基地址使用方式是否统一
- [x] 确认后端当前是否缺少 CORS 配置
- [x] 在后端增加本地开发环境 CORS 白名单
- [x] 允许至少以下来源访问：
  - `http://127.0.0.1:5173`
  - `http://localhost:5173`
- [x] 核对前端 `.env.example` 与后端 `.env.example`
- [x] 固化本地启动说明，避免前后端地址写死后失配

### 涉及目录

- `intelligen-frontend`

### 完成标准

- 前端本地请求后端不会被浏览器跨域拦截

- 能明确知道本地如何启动前后端

- 检查浏览器 Network 请求可正常返回

## Step 2. 冻结前后端接口契约

### 目标

把当前真正要联调的接口字段统一下来，避免前端和后端各自假设。

### 子步骤

- [x] 核对 `auth` 接口返回字段
- [x] 核对 `admin` 接口分页结构
- [x] 核对 `files` 接口字段命名
- [x] 核对 `templates` 返回中 `templateFileId`
- [x] 核对 `sessions` 创建与查询字段
- [x] 核对 `tasks` 返回状态码与字段
- [x] 明确任务状态接口统一使用 camelCase
- [x] 如代码与原文档冲突，以现行代码和本文件为准更新文档

### 当前冻结约定

- 所有业务接口统一返回：`{ code, message, data }`
- 登录返回中直接平铺：
  - `token`
  - `userId`
  - `username`
  - `nickname`
  - `email`
  - `role`
  - `authStatus`
  - `avatar`
- 模板选择字段统一为 `templateFileId`
- 任务状态字段统一为：
  - `taskId`
  - `sessionId`
  - `status`
  - `progress`
  - `currentSection`
  - `totalSections`
  - `resultMarkdown`
  - `errorMessage`
  - `updatedAt`

### 当前冻结接口快照

`POST /auth/login`

- 成功返回 `200`
- `data` 中直接包含：
  - `token`
  - `userId`
  - `username`
  - `nickname`
  - `email`
  - `role`
  - `authStatus`
  - `avatar`

`GET /admin/users/pending`

- 成功返回 `200`
- `data` 使用分页结构：
  - `list`
  - `page`
  - `pageSize`
  - `total`

`GET /files`

- 成功返回 `200`
- `data` 为数组，单项字段至少包含：
  - `fileId`
  - `fileName`
  - `fileUrl`
  - `fileType`
  - `fileSize`
  - `createdAt`

`GET /templates`

- 成功返回 `200`
- `data` 为数组，单项字段至少包含：
  - `templateId`
  - `name`
  - `description`
  - `templateFileId`

`POST /sessions`

- 成功返回 `200`
- 入参使用 `templateFileId`
- 返回字段至少包含：
  - `sessionId`
  - `title`
  - `templateFileId`
  - `createdAt`
  - `updatedAt`

`GET /tasks/{taskId}`

- 处理中返回 `202`
- 已完成返回 `200`
- 失败返回 `500`
- 不存在返回 `404`
- 统一返回 camelCase 任务字段，不透传下划线字段

### 完成标准

- 前端 API 调用不再依赖模糊字段推测
- 后端主链路接口字段有明确固定定义
- 契约差异点被记录进文档

### 验证方式

- 对照前端 API 文件和后端 DTO/Controller 逐项核对
- 必要时补或调整契约测试

## Step 3. 收紧后端模板与任务校验

### 目标

避免后端在模板、任务、模型服务依赖方面留下明显的数据一致性问题。

### 子步骤

- [x] 创建会话时，校验 `templateFileId` 不仅存在于 `files` 表，还必须存在于 `templates` 表
- [x] 明确模板不存在时的统一错误提示
- [x] 明确模板文件类型不合法时的错误提示
- [x] 明确模型服务未配置时的错误提示
- [x] 明确文件 URL 不可达或不可用时的错误提示边界
- [x] 核对任务失败时返回给前端的 message 和 data 是否稳定
- [x] 确认任务状态 200/202/500/404 行为稳定

### 涉及目录

- `intelligen-backend/src/main/java/com/intelligen/backend/session`
- `intelligen-backend/src/main/java/com/intelligen/backend/task`
- `intelligen-backend/src/main/java/com/intelligen/backend/template`
- `intelligen-backend/src/main/java/com/intelligen/backend/integration`

### 完成标准

- 任意文件不能被误当作模板文件创建会话
- 任务创建失败原因可以被前端稳定展示
- 模型服务相关错误不再是模糊失败

### 验证方式

- 补充或更新后端测试
- 手工构造非法 `templateFileId`、未配置模型服务等场景验证返回

### 当前已收口规则

- 创建会话时，如果 `templateFileId` 未登记为模板，统一返回：`模板不存在`
- 模板文件类型不合法时，统一返回：`模板文件类型仅支持 docx 或 pdf`
- 模型服务凭证未配置时，统一返回：`模型服务未配置`
- 如果模型服务是远程地址，而上传文件 URL 仍是 `127.0.0.1/localhost`，统一返回：
  `当前文件URL无法被远程模型服务访问，请检查 FILE_BASE_URL 配置`
