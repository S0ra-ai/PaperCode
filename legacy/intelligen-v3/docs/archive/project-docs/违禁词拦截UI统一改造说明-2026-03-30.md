# 违禁词拦截 UI 统一改造说明

> **版本**：2026-03-30  
> **状态**：✅ 已完成并部署

---

## 一、背景与需求

### 问题描述

系统中存在两种违禁词拦截后的界面提示风格，用户体验不一致：

| 情况 | 提示语（旧） | 风险等级 |
|---|---|---|
| 图一（正确风格） | `检测到严格类别敏感词: 苯丙胺` | high（暴恐、色情、涉枪涉爆等） |
| 图二（错误风格）| `检测到需要审核的内容，涉及类别: GFW补充词库` | medium（GFW补充词库、政治、贪腐等） |

### 用户需求

> "但凡被违禁词拦截了，就像图一一样，不要无中生有生出什么审核这些话术。"

**目标**：所有被拦截的情况，统一显示 **具体违禁词**，格式为 `检测到违禁词: xxx`，禁止出现"审核"等历史遗留话术。

---

## 二、根因分析

### 数据流链路

```
用户输入
  → 前端 WorkspaceView.vue 发起创建任务请求
  → Java 后端 TaskService → ModelStrategyClient 调用模型服务
  → Python 模型服务 content_safety.py 进行违禁词检测
  → 返回 403 响应
  → Java 后端透传给前端
  → 前端 SafetyBlockModal.vue 弹出提示
```

### 问题根因

Python 模型服务（`model_strategy`）对不同风险等级返回不同格式的消息：

```python
# high 等级（严格类别）→ 显示具体违禁词
return "high", "block", f"检测到严格类别敏感词: {具体关键词}"

# medium 等级（GFW等审核类）→ 显示类别名称，含"审核"话术
return "medium", "review", f"检测到需要审核的内容，涉及类别: {类别名称}"
```

**Java 后端问题**：收到 403 时，只把消息文本传给前端，**丢弃了** Python 返回的 `detected_keywords`（具体违禁词列表）字段。

**前端问题**：直接显示后端透传的原始消息，没有做统一处理。

---

## 三、改造方案

### 原则

> **不修改模型策略代码**（`model_strategy/`），只改前后端。

### 方案思路

Python 模型服务 403 响应的 `data` 字段中，**始终包含 `detected_keywords`（具体违禁词列表）**，但 Java 后端之前没有转发它。

解决方法：
1. **Java 后端**：从 403 响应里提取 `detected_keywords`，连同消息一起转发给前端
2. **前端**：收到 `detected_keywords` 后，自行构造统一格式的消息 `检测到违禁词: xxx`

## 四、具体改动

### 4.1 Java 后端：`ModelStrategyClient.java`

**文件路径**：`intelligen-backend/src/main/java/com/intelligen/backend/integration/model/ModelStrategyClient.java`

#### 改动 1：403 处理时传入 data 节点

```java
// 改前
if (code == 403) {
    throw BusinessException.forbidden(message, buildSafetyBlockPayload(message));
}

// 改后
if (code == 403) {
    JsonNode data = root.path("data");
    throw BusinessException.forbidden(message, buildSafetyBlockPayload(message, data));
}
```

#### 改动 2：`buildSafetyBlockPayload` 提取并转发 detected_keywords

```java
// 改前（只转发消息文本）
private Map<String, Object> buildSafetyBlockPayload(String message) {
    Map<String, Object> result = new HashMap<>();
    result.put("action", "block");
    result.put("msg", message);
    return result;
}

// 改后（同时提取 detected_keywords 列表）
private Map<String, Object> buildSafetyBlockPayload(String message, JsonNode data) {
    Map<String, Object> result = new HashMap<>();
    result.put("action", "block");
    result.put("msg", message);
    if (data != null && !data.isMissingNode() && data.has("detected_keywords") && data.get("detected_keywords").isArray()) {
        List<String> keywords = new ArrayList<>();
        for (JsonNode kw : data.get("detected_keywords")) {
            String kwStr = kw.asText("").trim();
            if (!kwStr.isEmpty()) {
                keywords.add(kwStr);
            }
        }
        if (!keywords.isEmpty()) {
            result.put("detected_keywords", keywords);
        }
    }
    return result;
}
```

### 4.2 前端：`WorkspaceView.vue`

**文件路径**：`intelligen-frontend/src/views/WorkspaceView.vue`

在 403 错误处理中，优先用 `detected_keywords` 构建统一消息格式：

```javascript
// 改前（直接显示后端原始消息）
if (error.code === 403) {
  safetyBlockData.value = {
    msg: error.message,
    ...error.data
  };

// 改后（用具体违禁词构建统一格式，有兜底）
if (error.code === 403) {
  const detectedKeywords = error.data?.detected_keywords;
  const displayMsg = (Array.isArray(detectedKeywords) && detectedKeywords.length > 0)
    ? `检测到违禁词: ${detectedKeywords.slice(0, 3).join(', ')}`
    : error.message;  // 兜底：拿不到关键词时显示原始消息
  safetyBlockData.value = {
    msg: displayMsg,
    ...error.data
  };
```

## 五、各风险等级行为对照

| 风险等级 | 对应词库 | action | 会触发拦截弹窗 | 改造后显示 |
|---|---|---|---|---|
| `critical` | 严重敏感词 + 生成请求 | `block` | ✅ 是 | `检测到违禁词: xxx` |
| `high` | 暴恐、色情、涉枪涉爆等 | `block` | ✅ 是 | `检测到违禁词: xxx` |
| `medium` | GFW补充词库、政治、贪腐等 | `review` | ✅ 是 | `检测到违禁词: xxx` |
| `low` | 广告、民生、其他词库 | `warn` | ❌ 否（任务正常执行） | 不弹窗 |
| `safe` | 无命中 | `allow` | ❌ 否 | 不弹窗 |

> **说明**：`low` 等级由 Python 模型服务判定为安全（`is_safe = True`），不返回 403，任务正常执行。如需拦截低等级违禁词，需修改模型策略代码（本次不在范围内）。

---

## 六、兜底降级策略

若 `detected_keywords` 为空或不存在（极端异常情况），前端会降级使用 `error.message` 作为弹窗消息，确保不会出现空白提示。

```
detected_keywords 有值 → "检测到违禁词: 具体词1, 具体词2"  ← 首选
detected_keywords 为空 → error.message（原始后端消息）     ← 兜底
```
