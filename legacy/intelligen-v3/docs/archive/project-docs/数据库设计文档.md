# 数据库设计文档

## 1. 概述

本文档详细描述了IntelliGen系统的数据库表结构，包括表名、字段名、数据类型、约束和描述。系统使用MySQL作为数据库管理系统，并支持后端接口 `POST /sessions/{sessionId}/tasks` 的任务提交与任务查询流程。

## 2. 数据库表结构

### 2.1 users表

**表说明**：用户表，存储用户的基本信息和认证状态。

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `userId` | `VARCHAR(36)` | `PRIMARY KEY` | 用户ID（UUID） |
| `username` | `VARCHAR(255)` | `UNIQUE NOT NULL` | 用户名 |
| `password` | `VARCHAR(255)` | `NOT NULL` | 密码（加密存储） |
| `nickname` | `VARCHAR(255)` | `NOT NULL` | 昵称 |
| `email` | `VARCHAR(255)` | `NOT NULL` | 邮箱 |
| `role` | `VARCHAR(50)` | `NOT NULL` | 角色（student/teacher/user/admin） |
| `authStatus` | `INT` | `NOT NULL` | 认证状态（0-未认证, 1-已认证, 2-已禁用） |
| `avatar` | `VARCHAR(255)` | | 头像URL |
| `createdAt` | `DATETIME` | `NOT NULL` | 创建时间 |
| `updatedAt` | `DATETIME` | `NOT NULL` | 更新时间 |

### 2.2 sessions表

**表说明**：会话表，存储用户的研究会话信息。

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `sessionId` | `VARCHAR(36)` | `PRIMARY KEY` | 会话ID（UUID） |
| `userId` | `VARCHAR(36)` | `NOT NULL` | 用户ID |
| `title` | `TEXT` | `NOT NULL` | 会话标题 |
| `templateFileId` | `VARCHAR(36)` | | 报告模板文件ID，对应 `files.fileId` |
| `createdAt` | `DATETIME` | `NOT NULL` | 创建时间 |
| `updatedAt` | `DATETIME` | `NOT NULL` | 更新时间 |

### 2.3 files表

**表说明**：文件表，存储用户上传的文件信息。

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `fileId` | `VARCHAR(36)` | `PRIMARY KEY` | 文件ID（UUID） |
| `userId` | `VARCHAR(36)` | `NOT NULL` | 用户ID |
| `fileName` | `VARCHAR(255)` | `NOT NULL` | 文件名 |
| `filePath` | `VARCHAR(255)` | `NOT NULL` | 文件路径 |
| `fileUrl` | `VARCHAR(500)` | `NOT NULL` | 文件可访问URL，供后端调用模型策略服务时使用 |
| `fileSize` | `BIGINT` | `NOT NULL` | 文件大小 |
| `fileType` | `VARCHAR(50)` | `NOT NULL` | 文件类型 |
| `createdAt` | `DATETIME` | `NOT NULL` | 创建时间 |
| `updatedAt` | `DATETIME` | `NOT NULL` | 更新时间 |

### 2.4 templates表

**表说明**：模板表，存储报告模板信息。

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `templateId` | `VARCHAR(36)` | `PRIMARY KEY` | 模板ID（UUID） |
| `name` | `VARCHAR(255)` | `NOT NULL` | 模板名称 |
| `description` | `TEXT` | | 模板描述 |
| `fileId` | `VARCHAR(36)` | `NOT NULL` | 模板文件ID |
| `createdAt` | `DATETIME` | `NOT NULL` | 创建时间 |
| `updatedAt` | `DATETIME` | `NOT NULL` | 更新时间 |

### 2.5 generate_tasks表

**表说明**：生成任务表，存储 `POST /sessions/{sessionId}/tasks` 提交后的任务信息、模型策略服务外部任务信息、任务进度和结果。

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `taskId` | `VARCHAR(36)` | `PRIMARY KEY` | 任务ID（UUID） |
| `sessionId` | `VARCHAR(36)` | `NOT NULL` | 会话ID |
| `externalTaskId` | `VARCHAR(64)` | | 模型策略服务返回的外部任务ID |
| `status` | `VARCHAR(50)` | `NOT NULL` | 任务状态（pending/processing/completed/failed） |
| `userInput` | `TEXT` | `NOT NULL` | 用户原始输入 |
| `outline` | `TEXT` | | 报告大纲 |
| `progress` | `DECIMAL(5,2)` | | 任务进度百分比，如 `45.50` |
| `currentSection` | `INT` | | 当前处理章节序号 |
| `totalSections` | `INT` | | 总章节数 |
| `resultMarkdown` | `LONGTEXT` | | 任务完成后的Markdown结果 |
| `errorMessage` | `TEXT` | | 任务失败原因 |
| `createdAt` | `DATETIME` | `NOT NULL` | 创建时间 |
| `updatedAt` | `DATETIME` | `NOT NULL` | 更新时间 |
| `completedAt` | `DATETIME` | | 完成时间 |

### 2.6 generate_task_files表

**表说明**：任务与文件关联表，存储 `POST /sessions/{sessionId}/tasks` 请求中的 `userFileIds`，支持一个任务关联多个用户文件、一个文件被多个任务复用。

| 字段名 | 数据类型 | 约束 | 描述 |
|-------|---------|------|------|
| `taskId` | `VARCHAR(36)` | `PRIMARY KEY`(联合) | 任务ID |
| `fileId` | `VARCHAR(36)` | `PRIMARY KEY`(联合) | 文件ID |
| `createdAt` | `DATETIME` | `NOT NULL` | 关联创建时间 |

## 3. 表关系说明

### 3.1 users表与sessions表
- 关系类型：一对多（One-to-Many）
- 关系说明：一个用户可以有多个会话
- 外键：sessions.userId → users.userId

### 3.2 users表与files表
- 关系类型：一对多（One-to-Many）
- 关系说明：一个用户可以上传多个文件
- 外键：files.userId → users.userId

### 3.3 sessions表与generate_tasks表
- 关系类型：一对多（One-to-Many）
- 关系说明：一个会话可以有多个生成任务
- 外键：generate_tasks.sessionId → sessions.sessionId

### 3.4 files表与templates表
- 关系类型：一对一（One-to-One）
- 关系说明：一个模板对应一个文件
- 外键：templates.fileId → files.fileId

### 3.5 sessions表与files表
- 关系类型：多对一（Many-to-One）
- 关系说明：一个会话可选绑定一个模板文件
- 外键：sessions.templateFileId → files.fileId

### 3.6 generate_tasks表与files表
- 关系类型：多对多（Many-to-Many）
- 关系说明：一个生成任务可以关联多个用户文件，一个文件也可以被多个任务复用
- 关联表：generate_task_files
- 外键：generate_task_files.taskId → generate_tasks.taskId
- 外键：generate_task_files.fileId → files.fileId

## 4. 索引建议

为了提高查询性能，建议在以下字段上创建索引：

### 4.1 users表
- `username`：唯一索引，用于登录和查询用户
- `email`：索引，用于邮箱查询和重置密码

### 4.2 sessions表
- `userId`：索引，用于查询用户的会话列表
- `createdAt`：索引，用于按时间排序查询

### 4.3 files表
- `userId`：索引，用于查询用户的文件列表
- `fileUrl`：索引，用于根据文件URL快速定位文件记录
- `createdAt`：索引，用于按时间排序查询

### 4.4 generate_tasks表
- `sessionId`：索引，用于查询会话的任务列表
- `externalTaskId`：索引，用于关联模型策略服务任务
- `status`：索引，用于按任务状态查询
- `createdAt`：索引，用于按时间排序查询

### 4.5 generate_task_files表
- `taskId`：索引，用于查询任务关联文件
- `fileId`：索引，用于查询文件被哪些任务引用

## 5. 数据库连接配置

### 5.1 JDBC连接配置（后端）

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/intelligen?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8
spring.datasource.username=intelligen
spring.datasource.password=your_password
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
```

### 5.2 Python连接配置（模型策略服务）

```python
import mysql.connector

config = {
    'user': 'intelligen',
    'password': 'your_password',
    'host': 'localhost',
    'database': 'intelligen',
    'port': 3306
}

cnx = mysql.connector.connect(**config)
```

## 6. 数据库初始化

### 6.1 创建数据库

```sql
CREATE DATABASE IF NOT EXISTS intelligen 
DEFAULT CHARACTER SET utf8mb4 
DEFAULT COLLATE utf8mb4_unicode_ci;

USE intelligen;
```

### 6.2 创建表结构

可以使用ORM框架（如JPA）自动创建表结构，也可以手动创建。

## 7. 数据备份与恢复

### 7.1 数据备份

```bash
mysqldump -u intelligen -p intelligen > intelligen_backup_$(date +%Y%m%d).sql
```

### 7.2 数据恢复

```bash
mysql -u intelligen -p intelligen < intelligen_backup_20240314.sql
```

## 8. 注意事项

1. 所有日期时间字段使用DATETIME类型，精确到秒
2. UUID字段使用VARCHAR(36)类型存储
3. 生成任务结果建议使用 `LONGTEXT` 存储Markdown内容，便于直接展示模型策略服务返回结果
4. 建议使用utf8mb4字符集以支持emoji等特殊字符
5. 定期备份数据库，防止数据丢失
6. 根据实际访问量优化数据库配置参数
